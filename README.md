# YTFE

Desktop application for **Windows 10/11** that downloads video and audio from the internet through a graphical interface.
Under the hood it uses [yt-dlp](https://github.com/yt-dlp/yt-dlp) (which supports YouTube and hundreds of other sites) and
[ffmpeg](https://ffmpeg.org/) to convert and merge the files.

- **Interface:** WPF on .NET 10 (C#), MVVM pattern.
- **Engine:** `yt-dlp.exe` runs as a child process. There is no embedded Python.
- **Languages:** Spanish and English, switchable instantly.
- **Theme:** light, dark or follow the system (WPF Fluent theme).
- **Logo and icon:** `Assets\app.ico` and `logo.png` (generated by code; each site's logo is a vector path in `SiteLogos.cs`).
- **Built-in help:** **Help** button or the **F1** key, with a search box and 13 topics in Spanish and English (`HelpContent.cs`).

---

## What it is for

- Download **video** choosing the resolution (up to 8K), container (MP4/MKV/WEBM) and codec (H.264/VP9/AV1).
- Download **audio only** as MP3, OGG, WAV, FLAC, M4A or Opus, choosing the bitrate.
- Download whole playlists/albums, trim a clip and use the **browser cookies** for sites that require a login.
- Manage several downloads at once: **pause, resume, cancel, retry and delete**.
- Keep the download list between sessions.
- Keep the external tools up to date without recompiling the application.

> **Use responsibly.** Download only content you have the right to download (your own, under a licence that allows it,
> or public domain) and respect each site's terms of use.

## Download and install

1. Go to [**Releases**](https://github.com/Damanium/YTFE/releases/latest) and download `YTFE-<version>-win-x64.zip`.
2. *(Recommended)* Before extracting: right-click the ZIP → **Properties** → tick **Unblock** → OK.
3. Extract it and run `YTFE.exe`. You do not need to install .NET: the executable includes it.

Every release includes the ZIP's **SHA-256** (in the notes and in `SHA256SUMS.txt`). To check it:

```powershell
Get-FileHash .\YTFE-1.1.1-win-x64.zip -Algorithm SHA256
```

And, if you have the [GitHub CLI](https://cli.github.com/), you can verify that the ZIP really came out of this
repository (build provenance attestation, available on releases produced by the automated workflow):

```powershell
gh attestation verify .\YTFE-1.1.1-win-x64.zip --repo Damanium/YTFE
```

### If Windows blocks the application

**The published versions are not digitally signed** (there are currently no plans to sign them). Windows distrusts programs without a signature
or reputation, and can react in three different ways:

| What you see | What it is | What to do |
|---|---|---|
| "Windows protected your PC" | **SmartScreen** (reputation) | Click **More info → Run anyway** |
| "An Application Control policy blocked this file" on your personal PC | **Smart App Control** | See below: there is no button to bypass it |
| The same message on a work or school PC | **WDAC / AppLocker** (organisation policy) | Ask whoever administers the machine to allow the application |

**Smart App Control (SAC)** is a Windows 11 protection that blocks every program that is not signed by a trusted
entity or is not well known. It does not allow per-application exceptions. Your options are:

- **Turn off Smart App Control** in *Windows Security → App & browser control →
  Smart App Control settings → Off*. While it is off, the machine is **less protected**
  against unknown programs: do it only if you understand the risk and trust the program's origin. On
  recent Windows 11 versions (with the 2026 updates) you can **turn it back on** from the same
  place whenever you want; on older versions, once turned off it could not be re-enabled without resetting or reinstalling
  Windows, so first check that your Windows is up to date and that the option lets you choose *On*.
- **Building it yourself does not avoid it**: an executable built locally is not signed either, so SAC blocks it
  just the same. That is why Microsoft recommends keeping SAC off on development machines.

> **Note about the downloaded tools.** On first launch YTFE downloads `yt-dlp.exe`, `ffmpeg.exe` and
> `deno.exe`, which are third-party programs and we are not their signers. With Smart App Control on they could
> be blocked too. This has **not been verified** on a Windows with SAC enabled.

Whatever the case, always download from the official [Releases](https://github.com/Damanium/YTFE/releases) page
and check the SHA-256.

## Build from source

```powershell
git clone https://github.com/Damanium/YTFE.git
cd YTFE
dotnet build
dotnet run --project src\YTFE
```

The executable ends up in `src\YTFE\bin\Debug\net10.0-windows\YTFE.exe`.

**First launch:** it downloads `yt-dlp.exe` (~22 MB), `deno.exe` (~40 MB) and `ffmpeg` (~200 MB).
You will see the progress in the status bar; until it finishes, the "Download" and "Analyze" buttons are disabled.
Later launches are instant.

## Usage

### Download a video or an audio file
1. Paste the **URL** in the top field (only `http://` and `https://` are accepted).
2. *(Optional)* Click **Analyze**: it shows the title, channel and duration, and replaces the resolution list with the ones
   that actually exist for that video.
3. Choose **Video** or **Audio only** and adjust the options.
4. Check the **Save to** folder (by default `Videos\YTFE`; **Browse…** to change it).
5. Click **Download** (or press Enter).

### Video options
| Option | Values |
|---|---|
| **Resolution** | Best available, 8K (4320p), 4K (2160p), 2K (1440p), 1080p, 720p, 480p, 360p, 240p, 144p |
| **Container** | **MP4** (most compatible), **MKV** (supports everything), **WEBM** (VP9/AV1 + Opus only) |
| **Codec** | Automatic, **H.264** (maximum compatibility), **VP9**, **AV1** (smaller size) |

- The resolution is a **cap**: if you choose 1080p and the video only goes up to 720p, it downloads 720p.
- The codec is a **preference**, not a filter: if the chosen one does not exist, it uses the next best.
- With **MP4 + Automatic** you may get VP9/AV1, which some Windows players handle poorly. For maximum
  compatibility choose **H.264**.
- **WEBM** is strict: if the video does not offer VP9/AV1 with Opus, the download may fail. In that case use MKV.

### Audio options
| Option | Values |
|---|---|
| **Format** | MP3, OGG (Vorbis), WAV, FLAC, M4A (AAC), Opus |
| **Quality (bitrate)** | Best quality, 320, 256, 192, 128 or 96 kbps |

- **WAV** and **FLAC** keep the original quality: the bitrate selector is disabled.
- "Best quality" for MP3 uses maximum VBR (V0); for the other formats yt-dlp decides.

### Common options
- **Embed metadata** (title, artist…).
- **Embed thumbnail / cover art**: disabled where it is not possible (WAV and WEBM).

### Managing downloads
Each download shows its title, a summary of what was chosen, a progress bar, status, speed and remaining time.
Only the buttons that make sense in its current state are shown; the other actions are in the **⋯** menu
or on **right-click**.

| Action | What it does | Available when |
|---|---|---|
| **Pause** | Stops the process and **keeps** what was downloaded | Downloading |
| **Resume** | Continues where it left off | Paused |
| **Cancel** | Stops the process and **discards** what was downloaded | Queued, downloading, processing, paused |
| **Retry** | Starts over | Error, cancelled |
| **Open** | Opens the file with the default program | Completed |
| **Show in folder** | Opens Explorer with the file selected | Always |
| **Copy link** / **Open in browser** | | Always |
| **Remove from list** | Removes the card, **without deleting files** | Completed, error, cancelled |
| **Delete files…** | Completed: sends the file to the **Recycle Bin**. Not completed: deletes only that video's partial files | Completed, paused, error, cancelled |

**Pause vs. Cancel**
- *Pause* = "I'll continue later": keeps the `.part` files and resumes with one click. You cannot pause while video and
  audio are being merged ("Processing"), because interrupting ffmpeg there would corrupt the file.
- *Cancel* = "I'm giving up": deletes the `.part` and temporary files **of that download** (never other files). It asks for
  confirmation only if it was already past 5 %. If you then press Retry, it starts from scratch.

**Global actions** (on the list): **Pause all**, **Resume all**, **Clear finished**.

**Concurrency:** 2 downloads run at a time; the rest wait in the queue. A paused download does not take a slot.

### Closing the application
- If there are downloads **in progress**, it asks before quitting. On exit they are stopped and left **paused**.
- When you reopen it, the list is restored. Half-finished downloads appear **paused** and **never start on their own**:
  press **Resume** whenever you like.

### Language
Drop-down in the bottom bar (Español / English). The change is immediate and remembered. The first time it uses your
Windows language (Spanish if Windows is in Spanish, English in any other case).

### Tools and updates
The bottom bar shows the installed versions (`yt-dlp · ffmpeg · deno`).

- **yt-dlp** is checked on its own **at startup, at most once every 24 h**. YouTube changes often and
  breaks the extractors; if downloads start failing, updating is usually the fix.
- The **Update tools** button updates yt-dlp, deno and ffmpeg, each one only if there is a newer version.
  ffmpeg and deno are **not** updated automatically (they weigh ~200 MB and ~40 MB). It does not update while downloads are running.
- While updating, "Download" and "Analyze" are blocked.

## Where it stores things

Everything under `%LOCALAPPDATA%\YTFE\`:

| Path | Contents |
|---|---|
| `tools\` | `yt-dlp.exe`, `ffmpeg.exe`, `ffprobe.exe`, `deno.exe` |
| `settings.json` | Language, theme and cookies browser |
| `state.json` | Date of the last automatic check and the ffmpeg version reference |
| `downloads.json` | Download list (saved automatically; restored on startup) |

Downloads are saved in the folder you choose (by default `Videos\YTFE`) with the name `Title [id].ext`.
To "start from scratch" just delete `%LOCALAPPDATA%\YTFE\`.

## Architecture

```
src/YTFE/
├── App.xaml(.cs)                     Startup: sets the language before creating the window
├── MainWindow.xaml(.cs)              Interface (bindings only; no business logic)
├── Models/
│   ├── DownloadOptions.cs            Chosen options → yt-dlp arguments; Choice<T>, VideoInfo, etc.
│   └── DownloadState.cs              States of a download
├── ViewModels/
│   ├── MainViewModel.cs              Main screen: options, list, global actions, persistence
│   └── DownloadItemViewModel.cs      One download: lifecycle, pause/cancel, deletion
├── Services/
│   ├── YtDlpService.cs               Launches yt-dlp, parses progress/title/id/path; URL analysis
│   ├── ToolsManager.cs               Downloads, versions and updates yt-dlp / ffmpeg / deno
│   ├── DownloadStore.cs              downloads.json (atomic write, validation on load)
│   └── AppSettings.cs                settings.json
├── Localization/
│   ├── Loc.cs, TExtension.cs         Language service and the {loc:T Key} XAML extension
│   └── Strings.cs                    All texts, in Spanish and English
└── Infrastructure/                   ObservableObject, RelayCommand, Dialogs
```

**How it talks to yt-dlp**
- Arguments are passed with `ArgumentList` (each one escaped) and the URL goes after `--`: there is no option injection.
- Progress is read with `--progress-template`; the title, id and final path with `--print`.
- `--encoding utf-8` is always passed. Without it, yt-dlp's `.exe` returns `?`/`�` instead of accents and ñ
  even if the environment is configured.
- **Pause** = kill the process while keeping the `.part` files; **resume** = relaunch (yt-dlp continues on its own).

### Common tasks for developers
- **Add a text:** one line `Add("Key", "español", "english")` in `Strings.cs`; in XAML `{loc:T Key}`,
  in code `Loc.T("Key")`. An untranslated key shows as `[Key]`.
- **Add a language:** add the code to `Loc.Supported`, another table in `Strings.cs` and an entry in `Languages`
  of `MainViewModel`.
- **Add a format or resolution:** adjust the lists in the `MainViewModel` constructor and, if needed,
  `DownloadOptions.ToArgs()`.

### Publishing a release

**Automated (recommended).** The [`.github/workflows/release.yml`](.github/workflows/release.yml) workflow builds on a
clean Windows machine, packages the ZIP, computes the SHA-256, generates the provenance attestation and creates the release:

```powershell
git tag v1.1.1
git push origin v1.1.1
```

It can also be launched by hand from the **Actions → Release → Run workflow** tab: it builds and leaves the ZIP as an
artifact of that run, but does not create any release.

> The automated workflow has already run successfully on GitHub (releases 1.1.0 and 1.1.1). Version 1.0.0 was built
> by hand with the command below.

**By hand.** It is the same command the workflow uses. It produces a single `YTFE.exe` of about 65 MB, with .NET included
(the ZIP weighs ~57 MB):

```powershell
dotnet publish src\YTFE -c Release -r win-x64 --self-contained `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true -o publish\win-x64
```

Version 1.0.0 was built this way and the executable was checked to start and respond. There is no installer (MSI/MSIX):
it is distributed as a portable ZIP.

### Code signing (for maintainers)

The workflow already includes the signing steps with [SignPath](https://signpath.org), which offers **free certificates for
open-source projects** (SignPath Foundation). They are **disabled** until the following is done:

1. **Apply for the certificate** from SignPath Foundation (the repository is public and the licence is MIT). Each project
   is reviewed by hand; approval is not guaranteed. *Status: not requested; there are currently no plans to sign.*
2. In SignPath, create the project, a release signing policy and an artifact configuration that expects a
   ZIP with `YTFE.exe` at the root, and install its GitHub connector.
3. In the repository (*Settings → Secrets and variables → Actions*):
   - **Secret** `SIGNPATH_API_TOKEN`
   - **Variables** `SIGNPATH_ORGANIZATION_ID`, `SIGNPATH_PROJECT_SLUG`, `SIGNPATH_SIGNING_POLICY_SLUG`
   - **Variable** `SIGNPATH_ENABLED` = `true` (the switch that turns signing on)
4. Add to this README the **code signing policy** that SignPath requires and the sentence
   *"Free code signing provided by SignPath.io, certificate by SignPath Foundation"*.

Alternatives if SignPath does not approve it: Azure Trusted Signing or a paid code-signing certificate;
in both cases only the steps marked "Code signing" in the workflow change.

## Known limitations

- **State of testing.** The interface has been run and several bugs have been fixed, but a **full manual test
  suite covering every button has not been done**. Verified with real yt-dlp: pausing and resuming a
  download, UTF-8 encoding and reading versions. There are no automated tests.
- The list is saved, but downloads **do not resume on their own** when reopening (on purpose).
- Playlists are downloaded with the "Download whole playlist / album" checkbox and appear as **a single row** (not tested with real playlists).
- There is no speed limit or download scheduling.
- Only the most common yt-dlp errors are translated (`ErrorHints.cs`); the rest appear as is, in English.
- Chrome/Edge/Brave cookies may not be readable while the browser is open; if that fails, it retries without cookies.
- The executables are not signed, so Windows may block them (see [If Windows blocks the application](#if-windows-blocks-the-application)).
- If a restored download is resumed before the initial tools check finishes, it could fail.
- When checking ffmpeg/deno versions the unauthenticated GitHub API is used (60 requests/hour; enough).
